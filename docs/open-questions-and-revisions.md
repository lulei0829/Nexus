# 待确认事项与历史修订

版本 v0.1 · 2026-11-04

本文件区分尚未确认的提案、已确认但未细化的规则，以及已被后续讨论覆盖的旧口径。不得将此处未定内容直接作为收费或开发验收依据。

## 一、尚未确认的具体提案

### 月费指定扣款钱包

历史聊天最后一轮建议：每份“主体＋端”订阅指定一个扣款钱包，默认该主体该端主业务钱包；有订阅权限的人员可改选同主体同端其他钱包；更换后历史欠费由新指定钱包补缴。

**该提案之后未见用户回复，不能写成已确认规则。**已确认的仅包括对应端未冻结可用余额扣缴、补缴优先及订阅归属。

### 订阅逐月对日等周期细节

曾提出洛杉矶时间逐月对日、缺日取月末、提前续期顺延等建议，用户随后明确更正“需要追补月费”。后续确认了停用继续累计、正式终止才停计、补清后沿原账期恢复，但未逐项确认完整周期方案。

因此，逐月对日、月末回归原日、重新开通的账期、提前续费及日比例补差算法，仍需完整确认，不能因为回复紧邻整段建议而推定全部采用。“未续费期间不追补月费”明确作废。

## 三、以最终确认替换的旧口径

| 旧说法或早期提案 | 当前有效口径 |
|---|---|
| 主商户可另开分销身份加入其他主商户 | 真实主体双向互斥，不能通过另开账号绕过 |
| 独立分销商可更换上级 | 分销上级固定，不能更换 |
| 店铺跨主商户重新授权即可迁移 | 禁止跨主商户，解绑重绑也不得绕过 |
| 各账号定制 SKU 永远不能共用 | 自建分别生成；同主商户授权迁移可共用，作品授权仍逐接收方检查 |
| 所有分销员工均由主商户统一管理 | 主商户与分销商分别管理岗位、员工，跨业务任职分别授权 |
| Nexus 是商品供货方，交易链为 Nexus→主商户→分销商 | 后续明确工厂供货交付，采购方与工厂签生产供货合同，主商户另有合作收益 |
| 一单多张质检包装主单 / 一计划一主单 | 同业务账号同销售订单一张主单，多计划多作业进明细 |
| 跨同一工厂厂区一律逐单审批 | 双方获主控预授权且全部条件满足，可自动跨厂区 |
| 原材料 BOM 明细账 | 厂区＋标准 SKU 可生产数量管理 |
| 每批排一部分即可对该部分启动自动开工 | 全计划排完启动计时，开工扣尚未扣减的计划数量 |
| 后台同步价改可更新既有订单 | 已匹配入单锁价，未匹配补齐时锁价，后续不覆盖 |
| 售后补发按原生产价且再收版权费或分销差额 | 金额由双方确认或仲裁；版权费、分销差额不重复产生 |
| 退款补发余额不足可无限形成负数直接执行 | 后续要求先解决信用超限，再批准执行 |
| 发货后各方收入一律即时可提现 | 授信且分销商欠款时，主商户收益待结算，相关分销商还清后释放 |
| 未续费不追补月费 | 停用期间继续累计，正式终止后停新增，历史欠费追补 |
| 月费钱包指定及跨钱包改选已定 | 最后一轮提案未回复，仍待确认 |
| 首期包含备货、成品库存、调拨 | 后续明确移出首期，保留作后续讨论资料 |
| 首期执行三个月归档与三年统一清理 | 历史数据处理已移出首期，不作为当前政策 |
| 5 分钟同步目标 | 用户改为 10 分钟；与导入校验的 10 分钟分别计时 |
| 每明细 7 张定制图 | 后续更正最多 6 张，前后左右上下 |
| 14 天是生产文件生成耗时 | 订单日期到全单质检包装的业务期限；生成性能另定 |
| 所有同步过来的新内容可以更正原单 | 原始内容锁定，缺失可补；校验不合格图片有保留版本及客户确认的限定例外 |
